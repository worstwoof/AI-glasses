# RV101 手机热点实时预览修复记录

验证日期：2026-10-08。工作分支：`codex/organize-aiglasses-monorepo`。

## 故障与定位

- 华为手机关闭 Wi-Fi，以移动数据上网并开启热点；手机热点地址 `192.168.43.1`，RV101 地址 `192.168.43.219`。
- 低频 JPEG 上传、HTTP offer/answer 均可成功，但此前手机 WebRTC 候选只有回环和蜂窝地址，没有热点地址；ICE 失败，视频解码帧数为 0。
- 当前 `flutter_webrtc 1.6.2+hotfix.3` 不读取 `disableNetworkMonitor` 初始化参数；单纯删除该参数不能解决问题。
- 原页面把收到视频轨道事件当作“视频已连接”。轨道协商成功不代表收到媒体帧，因此会出现“已连接”但黑屏。

## 实际修改

1. Android 新增 `HotspotNetworkDetector`，在 Flutter 初始化 WebRTC 前安装。保留标准网络监控，补充系统网络列表遗漏的、具有真实私有 IPv4 的 Wi-Fi/热点接口，并每 2 秒检查变化。
2. 补充接口使用 WebRTC Wi-Fi Direct 同类的 `NETWORK_UNSPECIFIED` 句柄 0；不伪造 Android 网络句柄，不将整个 App 绑定到热点，以保留移动数据访问千问的路径。
3. 固定直接引用与 Flutter 插件一致的 WebRTC Android 版本 `150.7871.01`。
4. `LanIcePolicy` 根据候选的实际地址选择与眼镜同网段的候选，排除回环/无效地址。不能将 `raddr` 中的地址误认作候选本身；无同网段候选时保留其他有效路径，不虚构热点候选。
5. SDP 和独立候选数组采用一致筛选规则。
6. 只有统计中的 `framesDecoded > 0` 才标记视频就绪；忽略已被替换连接的迟到统计结果。

## 真机结果

- 修复版本中，手机答复筛选为 2 个候选（原始 10 个），眼镜 offer 为 2 个候选。
- 手机已显示眼镜拍摄的真实桌面、包装等画面，随视角变化更新。
- 持续观察到视频约 **12 FPS**；解码帧数由 **903 → 2369 → 3039** 增长，码率约 **1296–1679 kbps**。
- 页面显示“ICE 局域网路径已连通”“控制 可抓拍”。这是视频与控制通道建立的证据，不只是 HTTP 信令成功。
- 加入首帧状态修正后再次构建、覆盖安装并进入实时预览，自动重建连接成功；新连接显示 **13 FPS / 1719 kbps / 412 帧**，顶部提示为“已收到眼镜实时画面”。
- APK 以覆盖安装方式更新，保留手机本地记录；构建从本机环境变量注入已有千问 Key，文档和源代码不写入 Key。

## 使用方式与剩余问题

1. 手机开启热点，眼镜连接此热点；本次验收使用手机移动数据上网。
2. 打开手机 App 的“识别 → 实时预览”，接收服务及眼镜发现由页面启动。
3. 页面显示真实画面、FPS 和增长的帧数后，才算预览成功。必要时使用“连接眼镜”重新建链。
4. USB 用于安装/调试；本次视频通过热点传输。
