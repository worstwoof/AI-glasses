# 包装 OCR 真机测试计划

## 1. 目标与范围

验证首版闭环：眼镜抓拍包装 JPEG，经手机端接收、OCR、营养字段解析和规则型风险筛查后，在健康管理 App 中展示包装图、OCR 原文、结构化营养信息和个性化提示。

本计划只验证包装食品分析，不验证菜品 VLM 识别，也不把包装识别结果自动写入饮食记录。

## 2. 运行前提

- 手机与 RV101 在同一 Wi-Fi 或手机热点中；手机端进入“识别 -> 实时预览”。
- 手机端显示控制通道可用，眼镜端 Camera2 已显示预览与实际选中的高清 JPEG 尺寸；策略是最接近 4032x3024 的可用 JPEG，不假定 1920x1080 为固定第二级回退。
- 通过 `--dart-define=AI_API_KEY=...` 注入 OCR 密钥；密钥不得写入源码、截图或记录表。
- 每张测试图记录唯一编号、包装类别、拍摄距离、光线、角度、抓拍分辨率、`captureSource` 和 OCR 耗时。
- 自动触发来自手机端 MediaPipe 的 OK pinch 手势，元数据为 `trigger=phone_ok_gesture`；它不是 RV101 已验证的物理“大拇指事件”。手动包装按钮使用 `trigger=packaging_button`。

## 3. 通过判定

- 眼镜上传 multipart 中 `metadata.type=packaging`，手机端打开“包装食品分析”页。
- `captureSource=high_res_jpeg` 时，页面使用接收器落盘的原始 JPEG，未经过 `ImagePicker` 的 `imageQuality` 或缩放。
- OCR 原文可查看和复制；能识别的营养字段显示数值和单位，不能识别的字段明确显示“未识别”。
- 对已识别的每 100 g / 每 100 mL 计量基准，按各自配置的规则输出高钠、高脂、高糖提示；配料可输出 canonical 过敏原、添加糖和需关注配料提示。
- 用户档案含匹配过敏原、疾病史、偏好或目标时，结果中出现“档案相关”的非诊断提醒。
- `captureSource=preview_fallback` 或 640 x 480 时，页面明确显示低清降级警告；基准未知时不进行高糖/高盐/高脂等级判定。

| I-02 | 速冻/即食食品，配料与营养表并列 | 1920 x 1080，高分 JPEG | 表格分区、产品标准号附近文本 | OCR 截断时可解析部分字段，缺失字段不填 0 |

| Q-02 | 镜面/高反光包装，强侧光 | 4032 x 3024，高分 JPEG | 反光遮挡、空白 OCR | 空白或明显缺行时显示可重试错误，不生成伪造营养值 |
| Q-03 | 有褶皱的零食袋 | 1920 x 1080，高分 JPEG | 褶皱导致的字符断裂 | 记录营养字段错误率、配料分隔错误与原图对应位置 |
| Q-04 | 小字号配料表（约 1.5-2 mm 字高） | 4032 x 3024，高分 JPEG | 小字、置信不足 | 记录可识别字段数与是否需要更近距离抓拍 |
| Q-05 | 斜拍包装（约 30-45 度） | 1920 x 1080，高分 JPEG | 透视变形 | 记录表格列错位、单位误读和透视矫正需求 |
| Q-06 | 抓拍瞬间移动，产生运动模糊 | 1920 x 1080，高分 JPEG | 模糊、重影 | OCR 失败须可重试；记录快门/曝光策略改进建议 |
| Q-07 | 裁切不全或高清失败，预览降级 | 640 x 480，`preview_fallback` | 半张标签、低清警告 | 显示低清降级警告；不把不完整字段当完整标签，不自动写入饮食记录 |

## 6. 已知边界

- 规则阈值只对已识别的每 100 g / 每 100 mL 基准生效，不是医疗诊断。
- 实测前不得对反光、曲面、模糊、斜拍或弯曲文字宣称识别通过。
- 如真实 OCR 的字段顺序不稳定，后续优先考虑旋转、透视矫正、局部裁剪、多帧选优和人工确认，不应默默补全数值。
