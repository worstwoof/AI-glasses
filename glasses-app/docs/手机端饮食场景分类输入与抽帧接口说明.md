# 饮食场景分类：图片输入与抽帧接口说明

## 1. 目的

本文只约定现有 AI 眼镜链路如何向场景分类模块提供图片。

当前输入不是视频文件，而是从 RV101 实时预览中按固定间隔抽取的**单张 JPEG 图片**。

```text
RV101 Camera2 实时预览
  -> 低频 JPEG 候选帧
  -> 手机端 HTTP 接收
  -> 场景分类模块（实现方式不限）
  -> 返回分类结果给手机端
```

## 2. 当前图片来源

眼镜端 Camera2 当前使用：

```text
格式：YUV_420_888
原始预览尺寸：640 x 480
```

眼镜端会将预览帧转成正向 JPEG：

```text
YUV_420_888 (640 x 480)
  -> NV21
  -> 旋转 270 度，校正为正向画面
  -> JPEG 压缩，质量 58
```

因此，分类模块收到的是：

```text
单张 JPEG
原始采集尺寸：640 x 480
视觉方向：旋转校正后通常约为 480 x 640 的竖向图片
最大允许文件大小：2 MB
```

分类实现应自行解码 JPEG，以实际解码后的宽高为准，不要假定图片一定是横向 `640 x 480`。

## 3. 当前上报间隔

眼镜端当前代码的候选帧上报间隔：

```text
FRAME_INTERVAL_MS = 1000 ms
```

即眼镜每秒最多向手机上传 `1` 张候选 JPEG。

这是图片到达手机的频率，不要求分类模块必须每秒处理一次。赵同学可以自行决定：

- 本地分类：可以处理每张候选图；
- 云端 API：建议只处理手机侧每 `3-5 秒`保留的最新一张，避免请求堆积、延迟和费用；
- 无论哪种方案，同一时刻最多保留一个分类任务在执行。

WebRTC 预览约为 `15 FPS`，仅用于手机页面实时显示；不要把 WebRTC 流或视频文件作为分类器输入。

## 4. 眼镜到手机的现有 HTTP 接口

眼镜发送候选帧的请求：

```text
POST http://<手机IP>:8080/api/v1/scene/frames
X-Device-Token: <pairing-token>
Content-Type: multipart/form-data; boundary=<generated-boundary>
```

表单字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `image` | JPEG 文件 | 分类模块的实际图片输入 |
| `metadata` | JSON 文本 | 调试辅助信息 |

当前 metadata 示例：

```json
{
  "deviceId": "RV101",
  "timestamp": 1786400000000,
  "sourceWidth": 640,
  "sourceHeight": 480,
  "format": "preview_jpeg"
}
```

`sourceWidth`、`sourceHeight` 是旋转前的 Camera2 原始帧尺寸，不能替代对 JPEG 图片本身的解码。

## 5. 现有眼镜端调用代码

当前眼镜端将 JPEG 图片作为 `multipart/form-data` 上传，核心逻辑如下：

```kotlin
private const val FRAME_INTERVAL_MS = 1_000L
private const val JPEG_QUALITY = 58

fun submit(image: Image) {
    if (!running) return
    val now = System.currentTimeMillis()
    if (now - lastSubmitMs < FRAME_INTERVAL_MS) return
    if (!uploading.compareAndSet(false, true)) return
    lastSubmitMs = now

    val width = image.width
    val height = image.height
    val nv21 = YuvFrameConverter.toNv21(image)

    worker.execute {
        try {
            val jpeg = YuvFrameConverter.toUprightJpeg(
                nv21,
                width,
                height,
                JPEG_QUALITY,
            )
            upload(jpeg, width, height)
        } finally {
            uploading.set(false)
        }
    }
}
```

实际文件：

[`PreviewFrameReporter.kt`](../app/src/main/java/com/example/rv101cameraprobe/PreviewFrameReporter.kt)

## 6. 手机端接收图片的位置

手机端当前在以下方法取得 JPEG 字节：

```dart
Future<void> _handleSceneFrame(HttpRequest request) async {
  final body = await _readBody(
    request,
    limit: _maxSceneFrameBytes + 256 * 1024,
  );
  final imageBytes = _parseMultipart(body, boundary)['image'];

  if (imageBytes == null || imageBytes.isEmpty) {
    // 缺少图片，返回 400
    return;
  }
  if (imageBytes.length > _maxSceneFrameBytes || !_isJpeg(imageBytes)) {
    // 非 JPEG 或超过 2 MB，返回 400
    return;
  }

  // imageBytes 即可交给赵同学实现的分类模块
  final result = await classifyScene(imageBytes);
}
```

实际文件：

[`glass_receiver_service.dart`](../../phone-app/lib/services/glass_receiver_service.dart)

赵同学的实现只需要能接收 `Uint8List imageBytes`（Dart）、`ByteArray`（Android/Kotlin）或上传到自己的 HTTP 服务的 JPEG 文件即可。

## 7. 最小返回约定

为方便手机端后续接入，分类模块建议至少返回：

```json
{
  "label": "meal_scene",
  "confidence": 0.88,
  "inferenceMs": 126
}
```

`label` 的具体类别可以由后续产品规则确定；本阶段最重要的是返回稳定的标签和置信度。若是云端服务，还建议附带模型版本和网络/服务耗时。

## 8. GitHub 协作方式

赵同学应基于当前双端联调代码创建独立功能分支开发，不直接修改 `main`。

当前基线分支：

```text
codex/organize-aiglasses-monorepo
```

建议功能分支：

```text
feature/meal-scene-classifier
```

首次获取代码并创建分支：

```powershell
git clone https://github.com/worstwoof/AI-glasses.git
cd AI-glasses
git switch codex/organize-aiglasses-monorepo
git pull origin codex/organize-aiglasses-monorepo
git switch -c feature/meal-scene-classifier
```

建议将分类相关的代码、配置和评估说明放在仓库根目录：

```text
scene-classifier/
├─ README.md
├─ train.ipynb
├─ requirements.txt
├─ labels.txt
└─ evaluation.md
```

训练或部署环境可以自行选择 Colab、Kaggle、个人服务器、本地模型或云端 API。仓库只应保留可复现所需的代码、配置和说明。

不要提交：

- 原始训练数据集、真实用户图片或眼镜采集图片；
- API Key、Token、热点密码和其他密钥；
- 大型 checkpoint、缓存和构建产物；
- 未确认体积和许可证的模型文件。

完成后提交并推送：

```powershell
git add scene-classifier
git commit -m "Add meal scene classifier experiment"
git push -u origin feature/meal-scene-classifier
```

随后在 GitHub 创建 Pull Request，目标分支选择：

```text
codex/organize-aiglasses-monorepo
```

PR 中应写明分类方案、输入输出约定、测试结果、已知限制和手机端接入建议。
