# RV101 眼镜端与手机端硬件接口总览

> 适用代码分支：`codex/organize-aiglasses-monorepo`
> 适用工程：`glasses-app/`（Rokid RV101）与 `phone-app/`（Android 手机）
> 更新时间：2026-08-11

## 1. 结论

当前方案是“手机主控 + RV101 眼镜采集”的局域网架构：

- 眼镜端负责 Camera2 取图、WebRTC 视频推送、低频 JPEG 上报和高清 JPEG 抓拍上传。
- 手机端负责发现眼镜、提供 HTTP 接收服务、返回 WebRTC Answer、渲染实时画面、发送抓拍命令，以及执行本地手势粗分类和后续 AI 分析。
- 眼镜和手机必须连接到同一 Wi-Fi 或手机热点。
- 视频、图片和控制命令均不使用蓝牙传输；实际链路是 HTTP + WebRTC。
- 当前不配置 STUN/TURN，不支持公网远程预览。

```text
手机 App
  HTTP 接收服务 :8080
  ├─ 接收 WebRTC Offer
  ├─ 接收低频场景 JPEG
  └─ 接收高清抓拍 JPEG
       ^
       | 同一 Wi-Fi / 手机热点
       v
RV101 眼镜 App
  HTTP 控制服务 :8088
  Camera2 -> WebRTC 视频、场景 JPEG、高清 JPEG
```

## 2. 硬件接口

### 2.1 眼镜端

代码没有定义 GPIO、UART、USB、BLE GATT 或厂商私有的物理引脚协议。眼镜端直接使用 Android 系统能力：

| 能力 | 代码接口 | 当前实现 |
|---|---|---|
| 摄像头 | Android Camera2 | 自动选择可输出 `YUV_420_888` 的相机 |
| 实时预览帧 | `ImageReader` | 目标尺寸 `640x480`，同一路帧供 WebRTC 和场景上报使用 |
| 高清抓拍 | Camera2 JPEG 输出 | 优先 `4032x3024`，其次 `1920x1080`，JPEG 质量为 95 |
| 网络 | Android Socket/HTTP/WebRTC | 通过 Wi-Fi 或手机热点与手机通信 |
| 运行保障 | 前台服务、WakeLock | 降低 Camera2 和网络采集被系统中断的概率 |

高清抓拍失败、超时或 JPEG 输出不可用时，眼镜端会保存并上传 `640x480` 的预览 JPEG 作为降级结果。

### 2.2 手机端

手机 App 是 Flutter 工程，Android 原生层提供 MediaPipe 手势分类。手机端虽然在 Manifest 中声明了蓝牙权限，但现有代码没有蓝牙扫描、配对、BLE GATT 或蓝牙传输实现；界面中的蓝牙图标不代表当前数据链路。

## 3. 网络前提和端口

| 设备 | 监听端口 | 用途 |
|---|---:|---|
| 手机 | `8080`，冲突时尝试 `8081`、`8082` | 接收图片、接收 WebRTC Offer 并返回 Answer |
| RV101 眼镜 | `8088` | 接收手机发现、启动和重连请求 |

手机进入“识别 -> 实时预览”后会读取本机 IPv4 地址，扫描同一网段的候选 IP 地址，并向候选地址的 `8088` 端口发送启动请求。最近一次成功的眼镜 IP 会保存在手机端偏好设置中，以便下次优先尝试。

常见热点地址是 `192.168.43.1`，但应用以运行时显示的手机地址为准。

## 4. 接口定义

所有眼镜到手机的请求，以及手机启动眼镜的请求，均需要携带：

```http
X-Device-Token: <pairing-token>
```

### 4.1 手机启动眼镜采集

```http
POST http://<眼镜IP>:8088/api/v1/glasses/start
Content-Type: application/json
X-Device-Token: <pairing-token>
```

```json
{
  "uploadEndpoint": "http://<手机IP>:8080/api/v1/captures",
  "token": "<pairing-token>"
}
```

眼镜端会校验请求头中的 token，保存上传地址和 token；服务尚未运行时启动 Camera2、WebRTC 和场景帧上报，已运行时重启 WebRTC 发布器以重新建链。

状态查询接口：

```http
GET http://<眼镜IP>:8088/api/v1/glasses/status
```

### 4.2 WebRTC 信令和实时视频

眼镜端根据上传地址自动推导信令地址：

```http
POST http://<手机IP>:8080/api/v1/webrtc/offer
Content-Type: application/json
X-Device-Token: <pairing-token>
```

```json
{
  "type": "offer",
  "sdp": "...",
  "candidates": [
    {
      "candidate": "...",
      "sdpMid": "0",
      "sdpMLineIndex": 0
    }
  ]
}
```

手机返回 `answer`、SDP 和 ICE candidates。眼镜端创建视频轨道并以约 15 FPS 推送预览画面。双方 ICE 配置为空，只使用同局域网候选地址。

同时，眼镜端创建一个名为 `rv101-control` 的 WebRTC DataChannel，用于接收抓拍控制命令。

### 4.3 手机请求高清抓拍

手机在 DataChannel 中发送：

```json
{
  "type": "capture",
  "trigger": "app_button",
  "timestamp": 0
}
```

眼镜收到 `type = capture` 后，调用 Camera2 拍摄高清 JPEG，并将结果上传到手机。

### 4.4 高清 JPEG 上传

```http
POST http://<手机IP>:8080/api/v1/captures
Content-Type: multipart/form-data
X-Device-Token: <pairing-token>
```

Multipart 字段：

```text
image: JPEG
metadata: JSON
```

`metadata` 当前包含：

```json
{
  "deviceId": "RV101",
  "timestamp": 0,
  "trigger": "app_button",
  "scene": "remote_preview",
  "sceneConfidence": 0.0,
  "width": 4032,
  "height": 3024
}
```

手机端仅接收 JPEG，限制为 20 MB；保存到应用文档目录的 `captures/` 中。成功时返回 HTTP `201`：

```json
{
  "accepted": true,
  "captureId": "capture_xxx",
  "status": "received"
}
```

### 4.5 低频场景帧上传

```http
POST http://<手机IP>:8080/api/v1/scene/frames
Content-Type: multipart/form-data
X-Device-Token: <pairing-token>
```

眼镜端从同一路 `640x480` 预览帧中约每秒取一帧，压缩为 JPEG（质量 58）发送。手机端限制场景帧不超过 2 MB，并调用本地 MediaPipe Hand Landmarker：

| 手势 | 手机端 scene | 当前含义 |
|---|---|---|
| OK | `ingredient_label` | 配料表/OCR 准备状态 |
| 张开手掌 | `eating` | 进餐环境准备状态 |
| 其他 | `unknown` | 等待 |

手机端需要连续两帧命中才确认上述状态，以减少误触发。

## 5. 完整运行顺序

1. 眼镜和手机接入同一个 Wi-Fi，或让眼镜接入手机热点。
2. 在眼镜上至少打开一次 `RV101 Camera Probe`，使 `8088` 控制服务处于待机或采集状态。
3. 手机打开 App，进入“识别 -> 实时预览”。
4. 手机启动本地 HTTP 接收服务并扫描同网段眼镜。
5. 手机向眼镜 `:8088/api/v1/glasses/start` 下发手机上传地址和 token。
6. 眼镜启动 Camera2，向手机发送 WebRTC Offer；手机返回 Answer 后显示实时视频。
7. 眼镜持续发送低频场景 JPEG；手机本地完成手势粗分类。
8. 用户点击“眼镜抓拍”时，手机经 DataChannel 请求眼镜拍照。
9. 眼镜上传高清 JPEG；手机保存图片并交给单张 AI 识图与饮食记录流程。

## 6. 当前实现边界

已经实现：

- 手机局域网扫描和眼镜控制服务；
- WebRTC 实时预览；
- DataChannel 手动抓拍；
- 低频 JPEG 上报和手机端 OK/张开手掌识别；
- 高清 JPEG 上传、保存和单张 AI 识图入口。

仅在设计文档中规划、尚未成为当前主链路自动行为：

- 握拳结束进餐；
- 基于 `food_scene` 的自动高清抓拍；
- `CaptureCoordinator` 调度器；
- 自动餐食记录状态机；
- 包装/配料表 OCR 的完整闭环。

## 7. 联调限制与安全注意事项

- 当前使用 HTTP 明文通信，Android 两端都允许 cleartext traffic；仅应在可信局域网或手机热点中使用。
- 当前 pairing token 有默认值并保存在本地偏好设置中，不是完整的设备身份认证方案；正式版本应改为首次配对随机 token、轮换和安全存储。
- 眼镜完整重启、应用刚安装或采集进程被系统杀死后，RV101 固件可能阻止第三方 App 的冷启动；此时必须先手动打开一次眼镜端 App。
- 相机可能被 Rokid 系统或其他应用占用；眼镜端会进入 busy 状态并按退避策略重试。
- 不要将真实用户图片、token、热点密码、APK 或构建输出提交到仓库。
