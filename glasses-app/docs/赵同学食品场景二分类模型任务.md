# 赵同学：食品场景二分类模型任务

## 1. 任务目标

在手机端实现一个轻量级图像二分类模型，对 RV101 眼镜上传的低分辨率候选图片进行判断：

```text
food_scene：画面中存在餐食、餐盘、饮料或正在进餐场景
not_food_scene：人物、手部、地面、墙面、空桌面、远景、模糊画面或其他无关场景
```

该模型只负责判断“当前画面是否值得作为餐食候选”，不负责识别具体菜品、估算分量、计算热量或识别包装配料表。

## 2. 工作环境

不要求拿到 RV101 眼镜实体，可以在电脑或云端完成训练：

- 推荐使用 Google Colab；
- 也可以使用 Kaggle Notebook；
- 本地电脑有 NVIDIA GPU 时可本地训练；
- 不需要在 Android Studio 中训练；
- 不需要把模型部署到眼镜端。

建议流程：

```text
公开数据集
  -> 训练和验证
  -> 导出 TFLite
  -> 测试手机端推理性能
  -> 提交模型和使用说明
```

## 3. 推荐技术路线

优先选择适合手机端部署的轻量模型：

- MobileNetV3；
- EfficientNet-Lite；
- MobileNetV2 也可以作为基线。

建议初始配置：

```text
输入：224x224 RGB 图片
输出：2 个类别
格式：TensorFlow Lite（.tflite）
量化：优先尝试 float16 或 int8
```

不要使用 30B 等大模型完成这个任务。二分类不需要复杂的大语言模型，轻量图像分类模型更适合手机端实时推理。

## 4. 数据要求

### 4.1 正样本 food_scene

应包含：

- 米饭、面条、汉堡、披萨、水果、饮料等餐食；
- 单个食物和多个食物；
- 餐盘、餐桌和不同餐具；
- 俯拍、第一视角、侧视角和不同距离；
- 明亮、偏暗、室内和室外等光照条件。

### 4.2 负样本 not_food_scene

应重点包含眼镜实际可能拍到的画面：

- 人物、手部和手势画面；
- 地面、墙面、天花板和走廊；
- 空桌面、空房间和远景；
- 模糊、过暗、过曝和严重遮挡图片；
- 货架、商品广告等暂时不希望自动触发的场景。

建议第一版每类至少准备 `500` 张图片，目标为每类 `1000` 张以上。训练集、验证集和测试集应按图片来源划分，不能把同一张图片的相似裁剪同时放进训练集和测试集。

注意：如果包装食品不希望被自动模式触发，包装图应放入 `not_food_scene`；如果项目后续希望自动采集饮料或包装食品，则需要重新定义标签并补充第三类或独立包装分类模型。

## 5. 训练与测试要求

训练完成后至少记录：

- 准确率（Accuracy）；
- Precision、Recall、F1；
- 混淆矩阵；
- `food_scene` 的召回率；
- `not_food_scene` 的误报率；
- 模型文件大小；
- 单张图片推理耗时。

重点关注误报率：自动拍摄不能因为地面、人物或货架画面频繁触发。

建议第一版验收目标：

```text
独立测试集准确率：>= 85%
food_scene Recall：>= 85%
模型文件大小：尽量 < 10 MB，最高不超过 20 MB
手机端单张推理：目标 < 300 ms，最高不超过 500 ms
```

这些是项目工程目标，不是 RV101 的官方硬件限制。模型文件大小和运行时内存占用是两个不同指标。

- 是否使用 float16 或 int8 量化。

## 7. 提供给手机端的接口

手机端每次传入一张低清 JPEG，模型返回统一结构：

```json
{
  "isFood": true,
  "label": "food_scene",
  "confidence": 0.87,
  "inferenceMs": 126
}
```

当 `confidence >= 0.80` 且连续两张候选帧均为 `food_scene` 时，手机端的 `CaptureCoordinator` 才允许提交自动高清拍摄任务。

如果模型返回 `not_food_scene` 或置信度不足，手机端应丢弃该候选帧，不触发高清拍摄。

## 8. 与现有系统的接入位置

当前链路为：

```text
RV101 Camera2 低清帧
  -> 手机 /api/v1/scene/frames
  -> 手机端手势/场景分类器
  -> CaptureCoordinator
  -> WebRTC DataChannel capture 指令
  -> RV101 高清 JPEG
  -> 手机 /api/v1/captures
```

二分类模型应替换或新增到手机端的低清帧分类位置。模型接入前，自动拍摄可以保持关闭，但手势拍摄、App 按钮拍摄和 OCR 链路仍应独立测试。

## 9. 暂不负责的内容

以下内容不属于赵同学本阶段任务：

- RV101 眼镜端 Camera2 采集；
- WebRTC 或 HTTP 上传链路；
- OK、张开手掌、握拳手势识别；
- 高清拍摄调度和冷却机制；
- 包装配料表 OCR；
- 具体菜品识别；
- 食品分量、热量和营养素估计；
- 饮食记录页面。

## 10. 最终验收

在没有眼镜实体的情况下，赵同学应使用独立测试集完成以下验证：

1. 餐食图片大多数判断为 `food_scene`；
2. 人物、地面、空桌、模糊图和货架图片大多数判断为 `not_food_scene`；
3. 模型可在手机端运行；
4. 单张推理结果包含标签、置信度和耗时；
5. 其他队员可以仅根据交接文档将模型接入现有手机 App。
